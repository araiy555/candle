# candle — kabuステーションAPI ローソク足自動売買システム

ローソク足パターンごとに独立した戦略で、底打ち検出・買い・損切り・トレーリングを行うシステムです。
段階的に開発しており、現在は第4段階（仮想売買）まで実装しています。

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | データ取得とローソク足生成 | 実装済み・実機で動作確認済み |
| 2 | パターン検出（7戦略） | 実装済み（毛抜き底は実機で検出を確認） |
| 3 | 戦略別バックテスト | 実装済み（過去データの用意が必要） |
| 4 | テスト（仮想売買）・管理画面 | 実装済み |
| 5 | 本番（実際に発注）・損切り・トレーリング | 実装済み（**実際の発注は未検証**。擬似環境でのテストのみ） |
| 6 | 少額運用検証 | これから |

## 3つのモード

`start.bat` をダブルクリックし、最初にAPIパスワードを入力すると、ブラウザで管理画面が開きます。
あとの操作と設定は、すべて管理画面で行います。起動直後は必ず「通知のみ」です。

| モード | 内容 |
|---|---|
| 通知のみ | サインを通知するだけで、売買はしません |
| テスト | 実際の株価で仮想的に売買します。注文は出ません |
| 本番 | 信用取引で実際に発注します。切り替え時に `yes` の入力が必要です |

モードは管理画面の左上のボタンで切り替えます。保有中のポジションがある間は切り替えられません。

**本番を使う前に、テストで数日動かして売買の内容を確かめてください。**
注文の形式は `python -m candle order-check`（検証用環境への送信）で確かめられます。

## 本番モードの動き

- 買い：サインが出た足の確定後、信用新規・成行で買います（既定は一般信用デイトレ、SOR）。
- 損切り：買いが約定したら、証券会社側に逆指値（成行）を置きます。PCが止まっても損切りは残ります。
- トレーリング：損切りラインが上がったら、逆指値を取り消して出し直します。
- 時間決済：15:20以降は新規を止め、逆指値を取り消して成行で返済します。
- 損切りラインとトレーリングの方式、金額の上限は、管理画面の「売買設定」で変更できます。

**安全のための決まり**

- 買い注文の結果が分からないとき（通信エラーなど）は再送せず、新規の買いを止めて知らせます。
- 同じ銘柄を同時に2つ持ちません。
- 逆指値を出せなかった場合は、プログラムが価格を監視して成行で決済する方式に切り替え、画面に警告を出します。
- プログラムの記録と実際の信用建玉が合わない状態が続くと、新規の買いを止めます。
- 管理画面の「緊急停止」は新規の買いを止めます。「全ポジションを決済」は保有分をすべて成行で返済します。

**注意**

- PCやkabuステーションが止まっている間は、トレーリングと時間決済は行われません。
  デイトレ信用の建玉は当日中の返済が必要なので、その場合は手動で返済してください。
- 手数料・金利・プレミアム料は損益に含めていません。

## 必要なもの

- kabuステーションを起動・ログインしたWindows PC（APIはそのPCの `localhost` でのみ動きます）
- kabuステーションの設定でAPIを有効にし、APIパスワードを設定済みであること
- Python 3.11 以上

## セットアップ（Windows / PowerShell）

```powershell
git clone https://github.com/araiy555/candle.git
cd candle
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy config.example.toml config.toml
$env:KABU_API_PASSWORD = "APIパスワード"
```

APIパスワードは `config.toml` やリポジトリには書かず、環境変数で渡します。

## 使い方

`start.bat` をダブルクリックすると、パスワードの入力 → 接続確認 → 起動 → 管理画面の表示までを行います。
管理画面でサインや監視銘柄の銘柄名をクリックすると、当日のチャート（サイン位置つき）が開きます。
通知モードは売買代金上位50銘柄を監視し、毛抜き底が出たらデスクトップ通知と音で知らせます（売買はしません）。
個別のコマンドは次のとおりです。

```powershell
python -m candle check            # 接続確認（トークン発行とランキング取得のみ）
python -m candle run              # 起動する（モードと設定は管理画面で操作。start.bat はこれを実行する）
python -m candle watch            # 上位50銘柄を監視し、サインを通知する（売買なし）
python -m candle notify-test      # 通知が届くかを試す
python -m candle live             # 本番: 実際に発注する
python -m candle order-check      # 検証用環境で注文の形式を確かめる
python -m candle paper            # テスト: 仮想売買＋管理画面 http://localhost:8765 （Ctrl+Cで終了）
python -m candle collect          # 足の収集だけ行う（売買判定なし）
python -m candle bars 7203        # 保存済みの足を表示
python -m candle import-yahoo 7203 6758   # Yahoo Financeから直近約60日の5分足を取り込む
python -m candle backtest         # 保存済みの足で戦略別バックテスト
python -m candle replay data/raw/20261124.jsonl   # 記録データから足を作り直す
```

検証用環境で試す場合は `config.toml` の `port` を `18081` にします。
`paper` は `collect` の機能を含むので、同時に動かす必要はありません。

## 戦略

7つのパターンをそれぞれ独立した戦略として扱い、サイン・取引・成績を戦略IDごとに分けて記録します。
いずれも検証候補であり、優位性が証明されたものではありません。

| 戦略ID | パターン | 成立条件の要点 |
|---|---|---|
| `tweezer_bottom` | 毛抜き底 | 陰線→陽線で安値がほぼ同じ |
| `bullish_engulfing` | 強気包み足 | 陽線の実体が直前の陰線の実体を包む |
| `hammer` | ハンマー | 下ヒゲが実体の2倍以上、上ヒゲが小さい |
| `morning_star` | 明けの明星 | 大陰線→小さな実体→1本目の半分を超える陽線 |
| `piercing_line` | 切り込み線 | 陰線の実体の半分を超えて戻す陽線 |
| `bullish_harami` | 強気はらみ線 | 大陰線の実体に収まる小さな陽線 |
| `double_bottom` | 二点底 | 近い水準の2つの底の後、間の高値を終値で上抜け |

加えて、ローソク足とは独立したシグナルとして **スクイーズ**（`squeeze`）があります。
板と約定の流れ（売り板の吸収、買い約定の連続、売り圧力への耐性）から、急騰前の需給の変化を
足の確定を待たずに検出します。約定の向きは配信からの推定で、しきい値は未検証の初期値です。
検知した内容とその後5分間の値動きは、上がったかどうかに関係なくすべて保存し、
管理画面の「スクイーズ検知履歴」（`http://localhost:8765/squeeze`）で一覧・集計・詳細を確認できます。
**FVG**（`fvg_hold` / `fvg_break`）も通知します。上昇の途中でできたFVGのうち、その上昇の割安ゾーン
（安値から高値までの下半分）にあるものを対象に、押し安値がFVGの上で止まって出来高を伴い反発すれば
「FVG反発（上昇継続）」、出来高を伴ってFVGを終値で下抜ければ「FVG割れ（上昇前のレンジのPOCまで戻る可能性）」
として知らせます。通知のみで、売買はしません。チャートには、上昇の範囲・割高/割安ゾーン・出来高の分布・
FVG・POCを重ねて表示します。

**大口の売り板**（`wall_break`）も観察します。売り板10本の中で、他の中央値の4倍以上・2,000万円以上の
売り注文が10秒以上出ている価格を「大口の売り板」とし、株価が近づいた後の結果を
「吸収して突破」「取消で消えた」「跳ね返された」の3つに分けて記録します。通知するのは
「吸収して突破」だけですが、3つとも検知履歴に残り、その後5分間の値動きを比べられます。

**流動性スイープ**（`liq_sweep`）も通知します。買った人たちの損切りがたまりやすい直近の押し安値
（流動性プール）を株価が割り込み、出来高を伴ってすぐに安値の上へ戻したときに知らせます。
損切りの売りを大口が受けて反転する動きを狙ったものです。通知と記録のみで、売買はしません。
チャートには、まだ割られていない押し安値を「流動性プール」として表示します。

流動性スイープには、起きた場面の印を付けて記録します：高値ブレイク（戻り高値を終値で上に抜けた）の
後かどうか、直近の上昇の割安ゾーン（下半分）かどうか、割ったのが内部流動性（当日安値より上の押し安値）か
外部流動性（当日安値）か。高値ブレイクの後に、割安ゾーンで内部流動性を割って戻したものは **内部流動性ブレイク**（`bos_dip`）として通知します。
分析ページで、場面ごとにその後の値動きを比べられます。

**寄り付き押し目**（`open_dip`）も通知します。9:00〜10:00の間、株価が始値より上（日足が陽線）で、
当日高値から2ティック以上押していて、買う価格（最良売り気配）の3ティック以内の下に厚い買い板
（他の買い板の中央値の4倍以上・2,000万円以上・3秒以上）があるときに、「買う価格／目標（+7ティック）／
損切りの目安（厚い買い板の1ティック下）」を知らせます。通知と記録のみで、売買はしません。
検知履歴には、5分以内に目標と損切りのどちらへ先に届いたかが残ります。寄り付き直後を狙うものなので、
「寄り付き後に待つ時間」の対象外です。

どのサインを通知するかは、管理画面の設定「通知するサイン」のチェックで選びます。

初期状態では通知のみで、売買の対象にするには `config.toml` の `[trading] strategies` に `squeeze` を加えます。

二点底以外は「直前30分が下落していて、パターン内で直近安値を付けている」ことも条件です。

**売買ルール（全戦略共通の初期設定）**

- 買い：サインが出た足の確定後、次の約定価格で買う。
- 初期損切り：パターン形成時の安値を下回ったら売る。買値との差を1Rとする。
- トレーリング：+1Rで損切りを建値へ、+2Rで+1Rへ、以降1R進むごとに追従。固定の利確はなし。
- 時間決済：15:20以降は新規停止・全決済（持ち越しなし）。

**リスク管理（全戦略共通）**：総投資上限、1銘柄上限、1日の最大損失、同一戦略の重複防止、
API切断中の新規停止、管理画面からの緊急停止。同一銘柄に複数戦略のサインが出た場合は、
戦略ごとに別のポジションとして持ちつつ、1銘柄上限と総額上限は共有します。
上限額は `config.toml` の `[risk]` で設定します（初期値は仮の値です）。

## 地合いの監視

個別株の買いが危険な場面を避けるため、相場全体の状態を3つの面から見ます（すべて5分前との比較）。

| 見るもの | 役割 | 判定 |
|---|---|---|
| 日経225先物 | 日本市場全体の方向 | 基準以上の下げで「警戒」 |
| TOPIX | 市場全体の広がり | 先物に加えてTOPIXも下げていれば「警戒強化」 |
| 監視中の銘柄 | 実際に個別株がどれだけ下げているか | 下落銘柄が基準（初期値70%）以上で「新規買い停止」 |

買いを止めるのは「新規買い停止」のときだけで、条件が外れてからも5分間は停止を続けます。
保有中の損切り・決済は通常どおり行います。基準は管理画面の設定で変えられます。
先物・TOPIXを受信できない場合は「取得できていません」と表示し、その項目は判定に使いません。
先物とTOPIXの分として、監視銘柄の枠を2つ使います（個別株は48銘柄になります）。

## バックテストの前提

- 次の足の始値で買い、同じ足で損切りと高値更新が両方起きた場合は損切りを先とみなします。
- 数量は1単元（100株）固定、スリッページ込み、手数料は0円として計算します。
- Yahoo Financeのデータは非公式で品質保証がないため、結果は参考値です。

## 仕様メモ

- **監視銘柄**：売買代金ランキング上位（既定45銘柄）。API登録上限は50銘柄で、残りは保有銘柄用の予備枠です。
  ランキングは平日7:53頃〜9:00過ぎは空になるため、その間に起動した場合は前回保存した監視銘柄を使います。
- **足の時刻**：東証の立会時間（9:00–11:30、12:30–15:30）のみ。引けちょうどの約定は最後の足に含めます。
- **出来高**：累積出来高の差分で計算します。
- **不完全な足**：足の途中から受信した場合や切断を挟んだ場合は `complete=0` で保存します。
  パターン検出には `complete=1` の足だけを使います。
- **約定のない5分間**は足を作りません。
- **記録**：受信データは必要項目だけ `data/raw/YYYYMMDD.jsonl` に保存します（板全体は保存しません）。
